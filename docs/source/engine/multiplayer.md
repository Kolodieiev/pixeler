### Мережева гра (Мультиплеєр)

Pixeler містить вбудовану підсистему для створення багатокористувацьких ігор у локальній мережі Wi-Fi без необхідності використання зовнішнього роутера чи інтернету (один мікроконтролер виступає точкою доступу та сервером, а інші підключаються до нього як клієнти, або всі пристрої працюють у спільній мережі маршрутизатора).

Мережевий стек побудовано поверх асинхронного протоколу **UDP (`AsyncUDP`)** із власним транспортним рівнем підтвердження доставки (**ACK**) для важливих пакетів та багатопотоковою обробкою черг у задачах FreeRTOS.

<br>

#### 1. Архітектура синхронізації: Авторитетний сервер

Мультиплеєр у Pixeler працює за моделлю **авторитетного сервера (Authoritative Server)**:

1. **Клієнт надсилає лише намір (Intent):** Коли гравець на клієнтському пристрої натискає кнопку або робить хід, клієнт **не змінює** стан гри локально. Натомість він формує `UdpPacket` із описом свого наміру (наприклад, *«хочу перемістити фігуру з A2 на A4»* або *«виконати дію X»*) і надсилає його серверу.
2. **Сервер валідує та виконує дію:** Сервер отримує пакет від клієнта, перевіряє, чи дозволена така дія правилами гри у поточний момент, і виконує її у власній ігровій сцені.
3. **Гарантована розсилка стану (Broadcast + ACK):** Після зміни стану сервер присвоює пакету новий унікальний `ID` і розсилає його всім клієнтам (`broadcast` або `send`), запускаючи відстеження підтверджень через **`AckTracker`**.
4. **Клієнти синхронізують стан:** Отримавши пакет від сервера з прапором `hasID() == true`, клієнт автоматично надсилає у відповідь пакет підтвердження (`SUBTYPE_ACK`), відсікає можливі мережеві дублікати і виконує дію у своїй сцені. Якщо хтось із клієнтів втратив пакет через завади Wi-Fi, сервер повторно надсилає йому останній пакет методом **`requestAcks()`** (до `MAX_RESEND_COUNT = 20` спроб).

Завдяки такій схемі всі підключені гравці завжди гарантовано синхронізовані зі станом сервера.

#### 2. Мережевий пакет (`UdpPacket`)

Клас **`UdpPacket`** (`#include "game/online/UdpPacket.h"`) успадкований від потоку байтів **`DataStream`** і є базовою одиницею обміну даними між сервером та клієнтами.

##### Внутрішня структура пакета
Максимальний розмір одного UDP-пакета становить **`MAX_PACKET_SIZE = 1000` байтів**, із яких перші **`PACKET_EXTRA_SIZE = 4` байти** зарезервовані під системний заголовок, а до **`996` байтів** доступні під корисні дані гри:

| Зміщення (Байт) | Призначення | Опис |
| :--- | :--- | :--- |
| **`[0]`** | `PacketType` | Основний тип пакета (`TYPE_PING`, `TYPE_GAME_DATA`, `TYPE_SERVICE_DATA`, `TYPE_CONNECT`). |
| **`[1]`** | `Subtype` | Підтип пакета (`uint8_t`). Для ігрових даних (`TYPE_GAME_DATA`) розробник може задавати власні коди підтипів команд. |
| **`[2]`** | `ID Flag` | Прапор наявності ідентифікатора (`1`, якщо пакет потребує підтвердження `ACK`, або `0`). |
| **`[3]`** | `Packet ID` | Порядковий номер пакета (`uint8_t`), за яким відстежується доставка `ACK` та фільтруються дублікати. |
| **`[4..999]`** | Корисні дані | Бінарні дані або рядки, записані через методи `DataStream` (`write`, `read` тощо). |

<br>

##### Типи та системні підтипи пакетів

* **`UdpPacket::PacketType` (Основні типи):**
  * `TYPE_PING` — перевірка активності з'єднання (кожні 2–4 секунди).
  * `TYPE_GAME_DATA` — обмін ігровими даними між сценами клієнта і сервера (тип за замовчуванням).
  * `TYPE_SERVICE_DATA` — сервісні команди керування життєвим циклом гри та `ACK`.
  * `TYPE_CONNECT` — пакети рукостискання та авторизації в лобі.
* **`UdpPacket::PackConnectSubtype` (Підтипи для `TYPE_CONNECT`):**
  * `SUBTYPE_HANDSHAKE` — перевірка ідентифікатора гри (`game_ID`).
  * `SUBTYPE_INCORRECT_SERVER` — `game_ID` клієнта не збігається з сервером.
  * `SUBTYPE_LOGIN` — передача нікнейму клієнта на сервер.
  * `SUBTYPE_INCORRECT_NAME` — нікнейм порожній, довший за 40 символів або вже зайнятий.
  * `SUBTYPE_ACCESS_GRANTED` / `SUBTYPE_ACCESS_DENIED` — рішення хоста про допуск клієнта в лобі.
  * `SUBTYPE_BUSY` — сервер закритий, заповнений або зараз розглядає запит іншого гравця.
* **`UdpPacket::PackServiceSubtype` (Підтипи для `TYPE_SERVICE_DATA`):**
  * `SUBTYPE_START_GAME` — команда всім клієнтам перейти з лобі до ігрової сцени.
  * `SUBTYPE_STOP_GAME` — команда завершити поточну гру.
  * `SUBTYPE_ACK` — автоматичне підтвердження отримання пакета з вказаним `ID`.

<br>

##### Основні методи `UdpPacket`

Оскільки `UdpPacket` успадковує `DataStream`, каретка читання/запису даних (`_index`) автоматично встановлюється на позицію `4` (одразу після системного заголовка).

| Метод | Опис |
| :--- | :--- |
| **`UdpPacket(size_t data_len)`** | Створює пакет із буфером під `data_len` байтів корисних даних (за замовчуванням тип `TYPE_GAME_DATA`). |
| **`setType(type)`**, **`getType()`** | Встановлює або повертає основний тип пакета (`PacketType`). |
| **`setSubtype(sub)`**, **`getSubtype()`** | Встановлює або повертає підтип пакета (`uint8_t`). |
| **`getData(pos)`**, **`getDataLen()`** | Повертає вказівник `const uint8_t*` на секцію даних зі зміщенням `pos` та загальний розмір корисних даних. |
| **`extractBytes(out, start, len)`** | Копіює `len` байтів із секції даних пакета у зовнішній буфер або структуру `out`. |
| **`dataToString()`** | Перетворює секцію даних пакета на нуль-термінований рядок `String`. |
| **`isDataEquals(buf, len, pos)`** | Побайтово порівнює дані пакета із буфером `buf`. |
| **`getIP()`**, **`getPort()`** | Повертають `IPAddress` та порт відправника пакета. |
| **`printToLog([char_like])`** | Виводить заголовок та вміст пакета у лог UART (у символьному або HEX-форматі) для налагодження. |

<br>

#### 3. Клієнтська сесія на сервері (`ClientSession`)

Кожен підключений до сервера гравець представлений об'єктом **`ClientSession`** (`#include "game/online/ClientSession.h"`), який передається у зворотні виклики сервера і дозволяє ідентифікувати відправника:

* **`session.getIP()`** / **`session.getPort()`** — повертають IP-адресу та порт клієнта.
* **`session.getName()`** / **`session.hasName(str)`** — повертають ім'я (нікнейм) гравця або порівнюють його з рядком.
* **`session.is(other_session)`** / **`session.is(remote_ip)`** — перевіряють, чи належить сесія вказаній IP-адресі.
* **`session.isConnected()`** — повертає `true`, якщо клієнт виходив на зв'язок або відповідав на `PING` протягом останніх **3 секунд**. Якщо клієнт мовчить понад **2 секунди** (`needsPing()`), фонова задача сервера автоматично надсилає йому `TYPE_PING`.
