### Терейн та карта світу (`Terrain2D`)

Клас **`Terrain2D`** (`#include "game/2D/Terrain2D.h"`) відповідає за формування, рендеринг та фізичну прохідність найнижчого графічного шару ігрової сцени. У кожній сцені (`IGameScene2D`) екземпляр терейну вже створено та доступно через захищене поле **`_terrain`**.

Терейн у Pixeler підтримує:
* Заливку базового фону сцени та багатошаровий **паралакс-ефект (`ParallaxLayer`)**.
* Побудову карти з квадратних плиток (**тайлів**), кожна з яких має власний тип прохідності (`TileType`).
* Два способи формування карти: **статичний** (із масивів, скомпільованих у прошивку) та **динамічний із SD-карти** (експорт карт із редактора **Tiled** та завантаження «на льоту» через `TerrainLoader2D`).

<br>

::: {important}
**Вимоги до розмірів карти та плиток:**
1. Усі плитки (тайли) мапи обов'язково повинні мати **квадратну форму** (наприклад, `16×16` або `32×32` пікселі).
2. Загальний розмір побудованого ігрового рівня у пікселях (`кількість_плиток × розмір_плитки`) має бути **не меншим за роздільну здатність дисплея (`UI_WIDTH × UI_HEIGHT`)**, інакше під час відмальовування виникне помилка.
:::

<br>

#### 1. Типи прохідності плиток (`TileType`)

Кожній плитці на карті призначається тип поверхні з переліку `TileType` (`#include "game/2D/TileType.h"`). Оскільки значення задані як бітові прапори (`1 << N`), їх можна комбінувати у бітові маски для гнучкого налаштування того, якими саме поверхнями може пересуватися конкретний ігровий об'єкт і як поверхня впливає на його швидкість.

| Константа `TileType` | Значення | Текстовий ключ для Tiled (`tp`) | Опис поверхні |
| :--- | :--- | :--- | :--- |
| **`TILE_TYPE_NONE`** | `0` | `none` | Плитка відсутня / невизначена зона |
| **`TILE_TYPE_WALL`** | `1 << 0` | `wall` | Стіна або нездоланна вертикальна перешкода |
| **`TILE_TYPE_GROUND`** | `1 << 1` | `ground` | Звичайна тверда земля / підлога |
| **`TILE_TYPE_WATER`** | `1 << 2` | `water` | Вода (для плавання або перешкода для піших об'єктів) |
| **`TILE_TYPE_AIR`** | `1 << 3` | `air` | Повітря / прірва (для літаючих об'єктів або платформерів) |
| **`TILE_TYPE_FIRE`** | `1 << 4` | `fire` | Вогонь |
| **`TILE_TYPE_SNOW`** | `1 << 5` | `snow` | Сніг |
| **`TILE_TYPE_MUD`** | `1 << 6` | `mud` | Багнюка / болото |
| **`TILE_TYPE_ROAD`** | `1 << 7` | `road` | Дорога / стежка |
| **`TILE_TYPE_TREE`** | `1 << 8` | `tree` | Дерево / лісова перешкода |
| **`TILE_TYPE_ICE`** | `1 << 9` | `ice` | Лід / слизька поверхня |
| **`TILE_TYPE_LAVA`** | `1 << 10` | `lava` | Лава |
| **`TILE_TYPE_IMPASSABLE`**| `1 << 15` | `impass` | Загальна непрохідна зона |
| **`TILE_TYPE_ALL`** | `0xFFFF` | — | Бітова маска всіх типів поверхонь одночасно |

Перевірити тип плитки у довільних піксельних координатах карти можна методом:

```cpp
TileType type = _terrain.getTileType(x, y);
```

#### 2. Спосіб А: Ручна побудова карти з масивів у прошивці

Для невеликих ігор або фіксованих рівнів масив карти та графічні спрайти плиток можна зберігати безпосередньо у Flash-пам'яті мікроконтролера. 

Побудова виконується у два кроки:
1. Реєстрація опису кожної унікальної плитки методом **`_terrain.addTileInfo(id, type, img_src)`**.
2. Генерація сітки рівня методом **`_terrain.build(tiles_w_num, tiles_h_num, tile_side_len, tmpl_array)`**.

```cpp
void SokobanScene::buildTerrain()
{
  // 1. Описуємо кожен тип плитки (ID плитки, тип прохідності, вказівник на RGB565 масив)
  _terrain.addTileInfo(0, TILE_TYPE_GROUND, IMG_TILE_0);
  _terrain.addTileInfo(1, TILE_TYPE_WALL, IMG_TILE_1);

  // 2. Задаємо розміри мапи у плитках та розмір сторони однієї плитки в пікселях
  uint8_t tiles_x_num{LVL_SIZE[_level][0]};
  uint8_t tiles_y_num{LVL_SIZE[_level][1]};
  uint8_t tile_width{32}; // Квадратна плитка 32x32 пікселі

  // 3. Будуємо мапу на основі одновимірного масиву-шаблону LVL_TEMPLATE[_level]
  _terrain.build(tiles_x_num, tiles_y_num, tile_width, LVL_TEMPLATE[_level]);
}
```

::: {note}
Якщо в межах однієї сцени потрібно повністю перебудувати рівень із новим набором плиток, перед повторним викликом `addTileInfo()` обов'язково очистьте попередній опис викликом **`_terrain.clearTilesInfos()`**.
:::

#### 3. Спосіб Б: Завантаження карти з SD-карти на льоту (`TerrainLoader2D` + Tiled)

Для великих ігор та RPG зберігати десятки карт і текстур у прошивці неефективно. Pixeler дозволяє створювати карти у популярному візуальному редакторі **[Tiled](https://www.mapeditor.org/)** і підвантажувати їх із SD-карти пам'яті на льоту за допомогою класу **`TerrainLoader2D`** (`#include "game/2D/TerrainLoader2D.h"`).

##### Підготовка файлів карти з редактора Tiled

Для завантаження рівня `TerrainLoader2D` очікує на SD-карті три складові:
1. **Каталог із `.bmp` зображеннями плиток** (формат **16-bit RGB565 BMP**), де ім'я кожного файлу відповідає `ID` плитки (наприклад, `0.bmp`, `1.bmp`, `2.bmp`).
2. **Файл шаблону карти `.csv`** — експортована з Tiled матриця розміщення плиток рівня (*File ➔ Export As ➔ CSV*).
3. **Файл метаданих прохідності плиток (наприклад, `tiles.meta`)** у форматі `id=тип`, згенерований із файлу набору плиток Tiled (`*.tsx`).

##### Як згенерувати файл типів плиток із `*.tsx`

У редакторі Tiled відкрийте ваш набір плиток (*Tileset*), виділіть потрібні плитки (Tiled підтримує масове виділення) і додайте їм кастомну рядкову властивість з іменем **`tp`** та значенням із таблиці `TileType` вище (наприклад: `ground`, `wall`, `water`, `road`).

Після збереження файлу `*.tsx` запустіть допоміжний Python-скрипт **`tile_type_extractor.py`**:

```python
import xml.etree.ElementTree as ET

TYPE_PROP_NAME = "tp"           # Ім'я властивості плитки в Tiled
INPUT_FILE = "test.tsx"         # Шлях до XML-файлу набору плиток (.tsx)
OUTPUT_FILE = "tiles.meta"      # Вихідний файл для TerrainLoader2D

tree = ET.parse(INPUT_FILE)
root = tree.getroot()
missing = []

with open(OUTPUT_FILE, "w", encoding="utf-8") as out:
    for tile in root.findall("tile"):
        tid = tile.get("id")
        prop_value = None

        props = tile.find("properties")
        if props is not None:
            for p in props.findall("property"):
                if p.get("name") == TYPE_PROP_NAME:
                    prop_value = (p.get("value") or "").strip()
                    break

        if prop_value:
            out.write(f"{tid}={prop_value}\n")
        else:
            missing.append(tid)

if missing:
    print(f"Відсутня властивість '{TYPE_PROP_NAME}' у плиток з id: {', '.join(map(str, missing))}")
else:
    print(f"Усі плитки мають властивість '{TYPE_PROP_NAME}'. Файл '{OUTPUT_FILE}' створено.")
```

Скрипт створить текстовий файл `tiles.meta` такого вигляду:
```ini
0=ground
1=wall
2=water
```

##### Завантаження та побудова терейну в C++ через `TerrainLoader2D`

Збережіть об'єкт `TerrainLoader2D` як поле вашої сцени (оскільки він володіє завантаженими в RAM/PSRAM текстурами плиток через власний `ResManager` протягом існування рівня) і викличте `loadTerrain()` та `buildTerrain()`:

```cpp
// 1. Завантажуємо шаблон карти (.csv), метадані типів (.meta) та папку з текстурами (.bmp)
if (_terrain_loader.loadTerrain("/maps/level1.csv", "/maps/tiles.meta", "/maps/tiles_bmp"))
{
  // 2. Будуємо _terrain сцени із завантажених даних (розмір плитки — 32 пікселі)
  _terrain_loader.buildTerrain(_terrain, 32);
}
```

При знищенні об'єкта `TerrainLoader2D` (або при ручному виклику `_terrain_loader.clearTerrainData()`) уся пам'ять, виділена під BMP-текстури плиток та шаблон карти, звільняється автоматично.

#### 4. Фон сцени та паралакс-шари (`ParallaxLayer`)

Для створення глибини простору (особливо у сайд-скролерах та платформерах) `Terrain2D` дозволяє додавати фонові шари, які малюються **під** плитками терейну та ігровими об'єктами.

##### Керування фоновою заливкою
За замовчуванням перед відмальовуванням кадру терейн заливає екран базовим фоновим кольором (`COLOR_BLACK`):
* **`_terrain.setBackColor(uint16_t color)`** — змінює колір фонової заливки (наприклад, колір неба).
* **`_terrain.setBackColorFilling(bool state)`** — вимикає або вмикає заливку фону на нульовому етапі рендерингу (варто вимкнути `false`, якщо ваші плитки або паралакс-шари гарантовано перекривають 100% екрана — це заощадить час процесора).

##### Додавання паралакс-шарів (`Terrain2D::ParallaxLayer`)
Структура `Terrain2D::ParallaxLayer` має три вбудовані фабричні методи для найпоширеніших типів фону:

1. **Статичний фон (`makeStatic`):** Завжди залишається нерухомим відносно екрана (наприклад, далеке сонце або місяць).
2. **Автоматичний рух (`makeAutoScroll`):** Безперервно пливе по горизонталі з фіксованою швидкістю `spd_x` пікселів за кадр незалежно від гравця (наприклад, хмари або туман).
3. **Класичний паралакс (`makeParallax`):** Зміщується пропорційно до руху камери з коефіцієнтом чутливості `ratio` (наприклад, далекі гори з `ratio = 0.2f` та ближній ліс із `ratio = 0.5f`).

```cpp
// 1. Статичне зображення неба/сонця у верхній частині екрана
_terrain.addParallaxLayer(
    Terrain2D::ParallaxLayer::makeStatic(IMG_SKY, 320, 120, 0, 0)
);

// 2. Хмари, які автоматично пливуть вліво зі швидкістю -0.5 пікселя/кадр
_terrain.addParallaxLayer(
    Terrain2D::ParallaxLayer::makeAutoScroll(IMG_CLOUDS, 320, 60, -0.5f, 0, 20)
);

// 3. Гори на задньому плані, що рухаються вдвічі повільніше за камеру і зациклені по осі X
_terrain.addParallaxLayer(
    Terrain2D::ParallaxLayer::makeParallax(IMG_MOUNTAINS, 320, 100, 0.5f, 0, 80, true)
);
```

Паралакс-шари відмальовуються строго в тому порядку, в якому вони були додані через `addParallaxLayer()`. Для видалення всіх фонових шарів використовується метод **`_terrain.clearParallaxLayers()`**.
