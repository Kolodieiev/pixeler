### Ігрова сцена (`IGameScene2D`)

Абстрактний клас **`IGameScene2D`** (`#include "game/2D/IGameScene2D.h"`) є центральним ядром будь-якого ігрового рівня у Pixeler. Сцена об'єднує та координує всі підсистеми ігрового світу: рендеринг карти, керування життєвим циклом ігрових об'єктів, перевірку колізій, відслідковування положення камери (viewport), програвання звукових ефектів та вивід поверхневого інтерфейсу (HUD / меню паузи).

<br>

#### Внутрішні компоненти та поля сцени

Кожен клас-спадкоємець `IGameScene2D` отримує доступ до таких захищених (`protected`) об'єктів та вказівників:

| Поле класу | Тип | Призначення |
| :--- | :--- | :--- |
| **`_terrain`** | `Terrain2D` | Найнижчий графічний шар сцени — тайлова мапа рівня та інформація про прохідність клітинок. |
| **`_sfx_player`** | `SfxPlayer` | Вбудований мікшер та плеєр звукових ефектів. Автоматично передається кожному створеному об'єкту. |
| **`_res_manager`** | `ResManager` | Менеджер для завантаження та кешування ресурсів (зокрема `.wav` файлів) у пам'яті. |
| **`_stored_objs`** | `DataStream&` | Посилання на спільний буфер контексту для збереження та перенесення стану об'єктів між сценами. |
| **`_main_obj`** | `IGameObject2D*` | Вказівник на головний ігровий об'єкт, за яким автоматично слідує камера (viewport) сцени. |
| **`_game_UI`** | `IGameUI*` | Необов'язковий поверхневий шар ігрового інтерфейсу (HUD: здоров'я, рахунок, індикатори). |
| **`_game_menu`** | `IGameMenu*` | Необов'язковий шар внутрішньоігрового меню (наприклад, меню паузи чи інвентар). |
| **`_is_paused`** | `bool` | Прапор постановки ігрового світу на паузу. |
| **`_is_finished`** | `bool` | Прапор повного завершення гри (сигналізує контексту про вихід із гри). |

<br>

#### Створення власної сцени: покроковий алгоритм

На прикладі сцени гри «Комірник» (`SokobanScene`) розглянемо обов'язкові етапи ініціалізації та роботи ігрової сцени.

##### 1. Реєстрація шаблонів спрайтів (`registerSpriteTemplate`)

Перш ніж створювати будь-які ігрові об'єкти, у конструкторі сцени необхідно зареєструвати **шаблони спрайтів (`SpriteTemplate`)** для кожного типу об'єкта (`type_ID`). Це потрібно для того, щоб важкі графічні дані та геометрія хітбоксів не дублювалися в кожному екземплярі об'єкта (наприклад, якщо на рівні 20 однакових ящиків).

```cpp
void SokobanScene::createSpiteTmpls()
{
  // Описуємо базову геометрію спрайта (розмір 32x32 пікселі та зміщення твердого тіла)
  SpriteGeometry sprite_geometry{
      .rigid_offsets{},
      .width = 32,
      .height = sprite_geometry.width,
  };

  // Шаблон для невидимих технічних об'єктів (наприклад, вільна камера)
  SpriteTemplate none_tmpl{};
  registerSpriteTemplate(TYPE_NONE, none_tmpl);

  // Шаблон для ящика з двома варіантами зображення (звичайний та встановлений на місце)
  SpriteTemplate box_tmpl{};
  box_tmpl.img_variants.push_back(SPRITE_BOX_NORMAL);
  box_tmpl.img_variants.push_back(SPRITE_BOX_DOCKED);
  box_tmpl.geometry_variants.push_back(sprite_geometry);
  registerSpriteTemplate(TYPE_BOX, box_tmpl);

  // Шаблон для головного персонажа
  SpriteTemplate hero_tmpl{};
  hero_tmpl.img_variants.push_back(SPRITE_SOKOBAN);
  hero_tmpl.geometry_variants.push_back(sprite_geometry);
  registerSpriteTemplate(TYPE_HERO, hero_tmpl);
}
```

::: {important}
Метод `registerSpriteTemplate(uint16_t type_ID, SpriteTemplate tmpl)` викликається **один раз на старті сцени** для кожного унікального `type_ID`. Спроба повторно зареєструвати шаблон для вже існуючого `type_ID` або створити об'єкт із незареєстрованим типом призведе до аварійного перезавантаження МК.
:::

##### 2. Побудова карти рівня (`_terrain`)

Наступним кроком у конструкторі сцени описуються типи плиток і будується мапа рівня через об'єкт `_terrain` (детальніше розглянуто в розділі [Терейн та карта світу](terrain.md)):

```cpp
void SokobanScene::buildTerrain()
{
  _terrain.addTileInfo(0, TILE_TYPE_GROUND, IMG_TILE_0);
  _terrain.addTileInfo(1, TILE_TYPE_WALL, IMG_TILE_1);

  uint8_t tiles_x_num{LVL_SIZE[_level][0]};
  uint8_t tiles_y_num{LVL_SIZE[_level][1]};
  uint8_t tile_width{32}; // Плитки обов'язково квадратні

  _terrain.build(tiles_x_num, tiles_y_num, tile_width, LVL_TEMPLATE[_level]);
}
```

<br>

##### 3. Створення об'єктів (`createObject`) та додавання у світ (`addObject`)

Для створення екземплярів ігрових об'єктів використовується шаблонний фабричний метод сцени **`createObject<T>()`**. Він автоматично генерує унікальний `ID` об'єкта та передає йому в конструктор посилання на саму сцену (`*this`) і звуковий плеєр (`_sfx_player`).

У Pixeler є важлива відмінність між просто створеним об'єктом та об'єктом, доданим до ігрового світу через **`addObject()`**:

* **Об'єкти, додані через `addObject(*obj)`:** Потрапляють до внутрішнього контейнера сцени `_game_objs`. Сцена автоматично бере на себе їхнє покадрове оновлення, рендеринг, перевірку колізій та **автоматично видаляє їх із пам'яті у своєму деструкторі**. Видаляти такі об'єкти вручну через `delete` **заборонено**!
* **Об'єкти, НЕ додані через `addObject()`:** (Наприклад, технічний об'єкт-привид `_ghost` для вільного польоту камери над картою). Вони не беруть участі у фізичних взаємодіях світу, і розробник **повинен видалити їх самостійно** у деструкторі своєї сцени (`delete _ghost;`).

```cpp
void SokobanScene::createGhost()
{
  // Створюємо об'єкт вільної камери (БЕЗ додавання у світ через addObject)
  _ghost = createObject<GhostObj>();
  _main_obj = _ghost; // Камера сцени слідкуватиме за цим об'єктом
}

void SokobanScene::createSokoban()
{
  // Створюємо персонажа та додаємо його до ігрового світу
  _sokoban = createObject<SokobanObj>();
  _sokoban->setPos(SOKOBAN_POS[_level][0], SOKOBAN_POS[_level][1]);
  addObject(*_sokoban); // Сцена сама видалить _sokoban при знищенні
}
```

##### 4. Керування камерою (`_main_obj`)

Камера ігрової сцени (область видимості або *viewport*) завжди автоматично центрується на об'єкті, адреса якого записана у вказівник **`_main_obj`**. 

Ви можете миттєво перемикати фокус камери між різними об'єктами просто під час гри у методі `update()`:

```cpp
if (_is_ghost_selected)
  _main_obj = _ghost;   // Камера літає за вільною точкою огляду
else
  _main_obj = _sokoban; // Камера слідує за гравцем
```

<br>

##### 5. Покадрове оновлення (`update()`)

Метод `void update() override` викликається керуючим контекстом на кожному кадрі. У ньому розробник описує реакцію на користувацький ввід та специфічну логіку рівня, після чого **обов'язково викликає базовий метод `IGameScene2D::update()`**:

```cpp
void SokobanScene::update()
{
  if (_input.isPressed(BtnID::BTN_BACK))
  {
    _is_finished = true; // Повідомляємо контекст про вихід із гри
    return;
  }

  // Керування об'єктами сцени...
  // ...

  // Обов'язковий виклик базового методу в кінці!
  // Саме він виконує post-задачі, оновлює всі об'єкти у світі та перемальовує кадр.
  IGameScene2D::update();
}
```

#### Пошук об'єктів та перевірка колізій на сцені

Клас `IGameScene2D` надає набір просторових методів, за допомогою яких сама сцена або будь-який об'єкт на ній можуть знаходити інші об'єкти за списком їхніх типів (`std::span<const uint16_t> type_ID`) та перевіряти прохідність:

| Метод сцени | Опис |
| :--- | :--- |
| **`getObjByType(types, [exclude])`** | Повертає вектор усіх об'єктів на сцені, тип яких збігається з переліком у `types` (опціонально ігноруючи об'єкт `exclude`). |
| **`getObjByTypeAt(types, x, y, [exclude])`** | Повертає всі об'єкти вказаних типів, що перекривають конкретну точку `(x, y)`. |
| **`getObjByTypeInRect(types, x, y, w, h, [exclude])`** | Повертає всі об'єкти вказаних типів, що перетинаються із заданою прямокутною областю. |
| **`getObjByTypeInCircle(types, x, y, r, [exclude])`** | Повертає всі об'єкти вказаних типів у радіусі `r` від центральної точки `(x, y)` (зручно для перевірки радіуса атаки, вибуху чи зони видимості NPC). |
| **`hasCollisionAt(x, y, [exclude])`** | Перевіряє, чи є в точці `(x, y)` будь-який об'єкт із увімкненим твердим тілом (хітбоксом). |
| **`canPass(caller, x_to, y_to)`** | Комплексна перевірка: чи може об'єкт `caller` з урахуванням габаритів його спрайта переміститися в точку `(x_to, y_to)` (перевіряє межі карти, прохідність плиток терейну та колізії з іншими твердими об'єктами). |

<br>

#### Система тригерів (`onTriggered`) та зміна сцени (`openSceneByID`)

Коли ігровий об'єкт досягає певної умови (наприклад, гравець наступив на телепорт або всі ящики встановлено на свої місця), об'єкт може повідомити про це сцену через систему тригерів.

Для перехоплення цих подій у класі вашої сцени достатньо перевизначити віртуальний метод **`onTriggered(uint16_t id)`**:

```cpp
void SokobanScene::onTriggered(uint16_t id)
{
  if (id == TriggerID::TRIGGER_NEXT_SCENE)
  {
    if (_level + 2 < 70)
      openSceneByID(_level += 2); // Запитуємо перехід на наступний рівень
    else
      _is_finished = true;        // Усі рівні пройдено — завершуємо гру
  }
}
```

Виклик **`openSceneByID(uint16_t scene_ID)`** встановлює номер наступної сцени та піднімає прапор `_is_released = true`, після чого керуючий контекст на наступному кадрі автоматично знищить поточну сцену та створить нову.

#### Серіалізація та потокобезпечність

* **Збереження стану об'єктів (`serializeObjects`):** Методи `calcObjectsSize()` та `serializeObjects(DataStream& ds)` дозволяють упакувати поточний стан усіх об'єктів сцени у потік байтів `DataStream` (наприклад, для збереження прогресу між переходами між локаціями або передачі стану по мережі).
* **Асинхронні виклики (`post`):** Аналогічно до `IContext`, сцена має власний потокобезпечний метод `post(std::function<void()> task, unsigned long timeout_ms = 0)`, який дозволяє безпечно передавати задачі з фонових потоків FreeRTOS (наприклад, мережеві події від ігрового сервера/клієнта) у потік оновлення сцени.
