### Користувацький ввід

Майже будь-який пристрій, для якого планується використання Pixeler, потребує зчитування та обробки користувацького вводу — будь то кишенькова ігрова консоль, MP3-програвач, пульт або виїзна панель керування.

Pixeler підтримує зчитування вводу з кількох незалежних джерел:
* Пряме підключення тактових або сенсорних кнопок до пінів GPIO мікроконтролера ESP.
* Зчитування стану кнопок з допоміжного мікроконтролера-співпроцесора по шині I2C.
* Сенсорний екран (тачскрін).
* Комп'ютерна USB-клавіатура (тільки для чипів із підтримкою USB-Host, наприклад ESP32-S3).

Перші два варіанти є взаємовиключними (не можуть використовуватися одночасно). Зчитування з тачскріна та клавіатури працюють незалежно і можуть комбінуватися з будь-яким основним джерелом вводу.

<br>

#### Реєстрація кнопок (GPIO)

Усі віртуальні кнопки реєструються та налаштовуються у файлі `src/config/input_config.h`. 

Якщо кнопки підключені безпосередньо до пінів ESP, визначення `EXT_INPUT` у конфігу повинно бути обов'язково закоментоване. Реєстрація виконується через перелік `BtnID` та макрос побудови мапи:

```cpp
// 1. Реєструємо ідентифікатори та прив'язуємо їх до пінів GPIO
enum BtnID : uint8_t
{
  BTN_OK = 10,
  BTN_LEFT = 12,
  BTN_RIGHT = 13,
};

// 2. Створюємо мапу кнопок (ID, об'єкт Button з вказівкою, чи є кнопка сенсорною)
#define BUTTONS_TMPL                         \
  {                                          \
      {BTN_OK, Button(BTN_OK, false)},       \
      {BTN_LEFT, Button(BTN_LEFT, false)},   \
      {BTN_RIGHT, Button(BTN_RIGHT, true)},  \
  }
```

<br>

#### Зчитування вводу по шині I2C (Співпроцесор)

Цей спосіб використовується, якщо для опитування кнопок задіяно окремий допоміжний мікроконтролер. 

Для його налаштування необхідно:
1. Запрограмувати допоміжний МК як ведений пристрій (Slave) на шині I2C.
2. Налаштувати піни I2C та адресу пристрою у файлах `src/config/i2c_config.h` та `src/config/coprocessor_config.h`.
3. Розкоментувати макрос `EXT_INPUT` у конфігурації вводу.

##### Протокол обміну командами по I2C
Основний МК (ведучий) надсилає команди, де першим байтом завжди передається номер команди:

| Команда (`CoprocessorCMD`) | Опис |
| :--- | :--- |
| `CCPU_CMD_ENABLE` | Необов'язкова. Увімкнення пристрою/периферії. |
| `CCPU_CMD_DISABLE` | Необов'язкова. Вимкнення пристрою/периферії. |
| `CCPU_CMD_PIN_ON` | Необов'язкова. Встановити пін у логічну 1. |
| `CCPU_CMD_PIN_OFF` | Необов'язкова. Встановити пін у логічний 0. |
| `CCPU_CMD_GET_BTNS_STATE` | **Обов'язкова.** Запит поточного стану всіх кнопок. |
| `CCPU_CMD_BTN_OFF` | **Обов'язкова.** Команда на деініціалізацію/вимкнення конкретної кнопки (для енергоощадження). |
| `CCPU_CMD_BTN_ON` | **Обов'язкова.** Команда на увімкнення конкретної кнопки. |

Команда `CCPU_CMD_GET_BTNS_STATE` очікує, що допоміжний МК поверне байти, в яких упаковано стан усіх кнопок (кожен біт відповідає реальній кнопці в порядку їх реєстрації). Наприклад, якщо встановлено макрос `EXT_INPUT_B_NUM 1`, головний МК зчитує 1 байт (до 8 кнопок).

* Отримане значення `0b10000000` означає, що натиснута лише перша кнопка (`BTN_PTT`).
* Отримане значення `0b01000010` — активні кнопки на позиціях 2 та 7.
* Зайві біти на позиціях, що перевищують кількість зареєстрованих кнопок, автоматично ігноруються фреймворком.

#### Обробка вводу в контексті

Стан кнопок є актуальним **тільки в методі `update()`** і не повинен перевірятися в `loop()`. Під час завантаження нового контексту стан усіх кнопок автоматично скидається до неактивного.

Pixeler дозволяє одночасно перевіряти кілька кнопок, що зручно для реалізації комбінацій при обмеженій кількості пінів:

```cpp
void MenuContext::update()
{
  // 1. Перевіряємо, чи кнопка утримується тривалий час (довге затискання)
  if (_input.isPressed(BtnID::BTN_BACK))
  {
    // Дія при довгому утримуванні
  }
  // 2. Перевіряємо, чи кнопка просто затиснута зараз
  else if (_input.isHolded(BtnID::BTN_UP))
  {
    // Дія при утримуванні
  }
  // 3. Перевіряємо, чи була кнопка натиснута та відпущена (клік)
  else if (_input.isReleased(BtnID::BTN_DOWN))
  {
    // Дія при кліку
  }
}
```

<br>

::: {warning}
**Важливо:** Метод `isPressed()` містить у собі перевірку `isHolded()`, тому `isPressed()` **завжди повинен перевірятися раніше**, ніж `isHolded()` для однієї і тієї ж кнопки. Якщо поставити перевірку `isHolded` першою, умова `isPressed` ніколи не виконається!
:::

<br>

#### Механізм захисту від повторних спрацьовувань (Блокування кнопок)

Після успішного зчитування стану певної події кнопки (наприклад, `isHolded`) фреймворк автоматично блокує цю кнопку на заданий час. Це запобігає випадковим подвійним спрацьовуванням, якщо користувач не встиг швидко відпустити палець.

Час блокування за замовчуванням задається у `input_config.h`, проте його можна змінювати «на льоту» через об'єкт `_input`:

```cpp
// Встановити час блокування в мілісекундах для різних подій
_input.setHoldLockTime(200);   // Після спрацьовування isHolded
_input.setClickLockTime(150);  // Після спрацьовування isReleased
_input.setPressLockTime(800);  // Після спрацьовування isPressed
```

<br>

#### Програмне вимкнення кнопок

За потреби окремі кнопки можна тимчасово вимкнути (наприклад, під час блокування екрана пристрою). Для сенсорних панелей це також допомагає знизити енергоспоживання:

```cpp
// Вимкнути кнопку
_input.disableBtn(BtnID::BTN_BACK);

// Увімкнути кнопку знову
_input.enableBtn(BtnID::BTN_BACK);
```

<br>

#### Сенсорний ввід (Тачскрін)

Pixeler підтримує роботу з ємнісними сенсорними екранами на контролерах **GT911** та **AXS15231B**.

Для активації у файлі `src/config/i2c_config.h` вказуються піни шини I2C та розкомендовується макрос `#define TOUCHSCREEN_SUPPORT` у `input_config.h`. Після цього у класі `Input` стають доступні методи для отримання координат та жестів:

```cpp
// Перевірка стану дотику (аналогічно до кнопок)
bool isTouchHolded = _input.isHolded();   
bool isTouchPressed = _input.isPressed(); 
bool isTouchReleased = _input.isReleased();

// Отримання координат останнього дотику
uint16_t x = _input.getTouchX();
uint16_t y = _input.getTouchY();

// Розпізнавання жестів гортання (Swipe)
ITouchscreen::Swipe swipe = _input.getSwipe();
```

Підтримуються 4 базові жести: `SWIPE_U` (вгору), `SWIPE_D` (вниз), `SWIPE_L` (вліво) та `SWIPE_R` (вправо). Логіка жестів побудована за принципом переміщення контенту (наприклад, жест згори вниз означає скролінг сторінки вгору).

<br>

#### Ввід з фізичної USB-клавіатури

::: {note}
Класична ESP32 не має апаратного контролера USB-Host, тому підключення USB-клавіатури можливе лише на чипах із підтримкою USB-OTG/USB-Host (наприклад, **ESP32-S3**). Увімкнення підтримки клавіатури споживає приблизно 15% вільної оперативної пам'яті (RAM) на S3.
:::

Для активації розкоментуйте `#define KEYBOARD_SUPPORT` у `input_config.h`. Після цього можна підписуватися на події клавіатури через колбеки:

```cpp
FilesContext::FilesContext()
{
  // Підписуємося на подію натискання клавіші
  _input.onKeyPressed(keyPressedHandler, this);
}

FilesContext::~FilesContext()
{
  // Обов'язково відписуємось у деструкторі
  _input.onKeyPressed(nullptr, nullptr);
}

void FilesContext::keyPressedHandler(const EspUsbHostKeyboardEvent& event, void* arg)
{
  FilesContext* self = static_cast<FilesContext*>(arg);

  switch (event.keycode)
  {
    case Input::KEY_UP_ARROW:
      self->post([self]() { self->up(); });
      break;
    case Input::KEY_ENTER:
      self->post([self]() { self->ok(); });
      break;
  }
}
```
