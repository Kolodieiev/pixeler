### Графічний інтерфейс користувача

Якщо у файлі конфігурації `config/graphics_config.h` оголошено макрос:

```cpp
#define GRAPHICS_ENABLED
```

у базовий клас контексту буде автоматично додано підтримку виводу графіки на дисплей.

Формування графічного інтерфейсу в Pixeler відбувається на основі **макета (Layout)**, який ініціалізується в класі контексту. Один і той самий контекст може мати декілька різних макетів GUI (наприклад, головний екран, діалогове вікно, екран помилки). Головне завдання розробника в такому разі — коректно налаштувати перемикання станів у машині станів контексту, щоб код помилково не звернувся до вже видаленого віджета через висячий вказівник (`dangling pointer`).

<br>

#### Віджети

**Віджет** — це базовий компонент графічного інтерфейсу, що має власний зовнішній вигляд, стан та логіку відрисовки. Наразі в Pixeler реалізовано такі віджети:

##### Базові елементи та контейнери
* **`EmptyLayout`** — базова панель-контейнер для компонування та групування інших віджетів.
* **`Label`** — текстове поле для виводу рядків.
* **`TextBox`** — успадкований від `Label` віджет, що слугує полем для вводу тексту або пароля користувачем.
* **`Image`** — віджет для формування і виводу зображень на дисплей із масивів пікселів (бітових мап).

##### Елементи керування та індикації
* **`ToggleSwitch`** — перемикач для відображення та зміни бінарного стану («увімкнено / вимкнено»).
* **`SpinBox`** — елемент керування, який дозволяє циклічно обирати числові значення із заданого діапазону.
* **`ProgressBar`** — смуга прогресу для візуалізації ступеня виконання тривалої задачі.
* **`ScrollBar`** — індикатор поточної позиції прокручування списку.
* **`Keyboard` та `KeyboardRow`** — віджети для формування кастомних розкладок екранної (віртуальної) клавіатури.

##### Списки та меню
* **`FixedMenu` та `DynamicMenu`** — контейнери для візуалізації вертикальних або горизонтальних списків, що мають принципові відмінності в роботі з пам'яттю:
  * **Фіксоване меню (`FixedMenu`)** — формується в оперативній пам'яті одразу повністю, незалежно від кількості елементів. Пункти меню можна додавати та видаляти по одному в будь-який момент.
  * **Динамічне меню (`DynamicMenu`)** — підвантажує елементи частинами під час прокручування списку, щоб мінімізувати споживання RAM на великих переліках (наприклад, вміст SD-карти). Кожна нова порція даних заміщує попередню. Контроль підвантаження даних організовує розробник, а `DynamicMenu` надає зручний інтерфейс і гарантує виклик обробників прокрутки.
* **`MenuItem`** — базовий елемент списку меню, що містить текстовий підпис (`Label`) та опціональну іконку (`Image`). Від нього успадковано спеціалізовані інтерактивні пункти меню:
  * **`ToggleItem`** — пункт меню з вбудованим перемикачем `ToggleSwitch`.
  * **`SpinItem`** — пункт меню з вбудованим числовим селектором `SpinBox`.
  * **`ComboItem`** — пункт меню з прокручуваним списком текстових варіантів вибору.

<br>

#### Контейнер віджетів

**Контейнер віджетів (`IWidgetContainer`)** — це спеціальний тип віджета, який зберігає в собі дочірні віджети, керує їхньою пам'яттю та викликає їхнє відмальовування. Контейнер дозволяє виконувати пошук та видалення вкладеного віджета за його унікальним ідентифікатором (`ID`).

Контейнери підтримують вкладеність: один контейнер може бути доданий всередину іншого контейнера.

<br>

::: {important}
Ідентифікатори віджетів (`ID`), які додаються до контейнера, повинні бути **більшими за `0`** та **унікальними** в межах свого безпосереднього контейнера. Під час спроби додати до контейнера віджет із некоректним або дубльованим ідентифікатором буде примусово викликано перезавантаження прошивки.
:::

<br>

#### Клонування віджетів

Щоб зменшити обсяг шаблонного коду під час створення однотипних елементів інтерфейсу, замість ручного створення та повторного налаштування кожного віджета доцільно використовувати вбудований механізм клонування (`clone(uint16_t id)`):

```cpp
// Створюємо базовий віджет зображення та налаштовуємо його один раз
Image* _img_back_normal = new Image(1);
_img_back_normal->setWidth(IMG_W);
_img_back_normal->setHeight(IMG_H);
_img_back_normal->setSrc(BTN_BACK_NORMAL);
_img_back_normal->setBackColor(COLOR_MAIN_BACK);
_img_back_normal->setTransparency(true);

// Налаштовуємо перший текстовий віджет
Label* lbl_online = new Label(1);
item_online->setLabel(lbl_online);
lbl_online->setAlign(IWidget::ALIGN_CENTER);
lbl_online->setGravity(IWidget::GRAVITY_CENTER);
lbl_online->setTextColor(COLOR_BLACK);
lbl_online->setBackImg(_img_back_normal->clone(1)); // Клонуємо фонове Image
lbl_online->setText(STR_MULTI_GAME);
// ...

// Клонуємо вже налаштований Label для наступного пункту меню
Label* lbl_pref = lbl_online->clone(1);           
item_pref->setLabel(lbl_pref);
lbl_pref->setBackImg(_img_back_normal->clone(1)); // Клонуємо фонове Image
lbl_pref->setText(STR_PREFERENCES);               // Змінюємо лише текст
```

Виклик `clone()` у контейнера віджетів рекурсивно склонує і всі вкладені в нього дочірні елементи (створюється повна глибока копія дерева віджетів).

<br>

#### Позиціонування та система координат

Початок координат `[0, 0]` знаходиться у **верхньому лівому куті** екрана (вісь `X` спрямована вправо, а вісь `Y` — вниз).

Усі вкладені віджети в макеті позиціонуються **відносно свого батьківського контейнера** з урахуванням додаткового зміщення **`+1 піксель`** під рамку контейнера:

*   **X (екран)** = `X (контейнера)` + `X (віджета)` + 1
*   **Y (екран)** = `Y (контейнера)` + `Y (віджета)` + 1

Наприклад, якщо батьківський контейнер має координати `[10, 5]`, а вкладений у нього віджет має локальні координати `[5, 5]`, то на фізичний дисплей цей віджет буде виведено в абсолютних координатах **`[16, 11]`** (`[10 + 5 + 1, 5 + 5 + 1]`).

<br>

#### Правила малювання віджетів

* **Самостійний рендеринг:** Кожен віджет має прямий доступ до графічного буфера (`Canvas`) драйвера Pixeler і самостійно відмальовує себе відповідно до власних налаштувань.
* **Часткове оновлення (Dirty State):** Кожен віджет відстежує зміну власного стану. Якщо властивості віджета не змінювалися в поточному кадрі, він пропускає своє малювання, економлячи час процесора.
* **Поведінка контейнера:** Якщо сам контейнер не змінював свого стану, він пропускає заливку власного фону/рамки, але по черзі викликає перевірку малювання для всіх вкладених у нього віджетів.
* **Каскадне перемальовування:** Якщо було оновлено стан самого контейнера віджетів, усі вкладені в нього дочірні віджети будуть примусово перемальовані поверх нового фону контейнера.
* **Вимкнення видимості:** Якщо контейнер або віджет вимкнено (`setVisibility(IWidget::INVISIBLE)` / вимкнено стан), він повністю пропускає своє малювання та перемальовування всіх дочірніх елементів.
* **Порядок накладання (Z-order):** Віджети відмальовуються строго в тому порядку, в якому вони були додані до свого контейнера (останній доданий малюється поверх попередніх).

#### Встановлення макета графічного інтерфейсу

Хоча технічно будь-який віджет можна вивести на `Canvas` напряму без прив'язки до макета контексту, робити це не рекомендується, оскільки вам доведеться вручну контролювати звільнення пам'яті, координати та перемальовування.

Щоб встановити або замінити головний макет для поточного контексту, використовується метод:

```cpp
setLayout(layout);
```

де `layout` — вказівник на будь-який віджет-контейнер (зазвичай `EmptyLayout`). Рекомендується задавати розміри кореневого контейнера на повний розмір вікна (`UI_WIDTH` × `UI_HEIGHT`), оскільки він одночасно виконує роль базового тла екрана.

Приклад початкової ініціалізації та встановлення макета в конструкторі контексту:

```cpp
MenuContext::MenuContext()
{
  // Створюємо за допомогою шаблонізатора новий порожній макет на весь екран,
  // який буде кореневим контейнером для GUI
  EmptyLayout* layout = WidgetCreator::getEmptyLayout();

  // Прив'язуємо цей макет до поточного контексту
  setLayout(layout);

  // Створюємо віджет меню з унікальним ідентифікатором,
  // за яким зможемо знайти його на макеті за потреби
  FixedMenu* menu = new FixedMenu(ID_MENU);

  // Додаємо меню до кореневого макета
  layout->addWidget(menu);

  // Налаштовуємо зовнішній вигляд меню та додаємо елементи списку
  // ...
}
```

Кореневий макет можна динамічно замінювати на інший у будь-який момент існування контексту — при виклику `setLayout(new_layout)` старий макет разом з усіма його дочірніми віджетами буде автоматично видалено з пам'яті.
