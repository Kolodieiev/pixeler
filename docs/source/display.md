### Підключення дисплея

Pixeler підтримує вивід зображення на дисплей через модифіковану та оптимізовану бібліотеку **`Arduino_GFX`**. Підтримується більшість кольорових TFT/IPS дисплеїв із оригінальної бібліотеки (за винятком монохромних або повільних дисплеїв, що працюють виключно по шині I2C). 

Одночасно фреймворк може працювати лише з одним дисплеєм.

Усі базові налаштування графічної підсистеми та екрана знаходяться у файлі `/src/config/graphics_config.h`. Щоб уніфікувати підключення різних комбінацій шин та контролерів матриць, конфігурація задається через макроси, значення яких підставляються в код ініціалізації на етапі компіляції.

<br>

#### 1. Налаштування шини даних (`BUS_TYPE`)

Спочатку необхідно вказати клас шини, за якою підключено дисплей (наприклад, `Arduino_ESP32SPI`, паралельна шина чи QSPI), та передати її параметри:

```cpp
// Клас шини передачі даних
#define BUS_TYPE Arduino_ESP32SPI   

// Прапор, який вказує, чи є шина спільною для декількох пристроїв 
// (насамперед актуально для SPI, коли на одній шині висять дисплей та SD-карта)
#define IS_COMMON_BUS false    

// Параметри, які передаються до конструктора класу шини
#define BUS_PARAMS TFT_DC, TFT_CS, TFT_SCLK, TFT_MOSI, TFT_MISO, SPI_PORT, IS_COMMON_BUS  

// У коді ініціалізації ці макроси розгортаються у створення об'єкта:
BUS_TYPE _bus{BUS_PARAMS};
```

<br>

#### 2. Налаштування драйвера дисплея (`DISP_DRIVER_TYPE`)

Після налаштування шини вказується клас контролера вашого дисплея (наприклад, `Arduino_ST7789`, `Arduino_ILI9341` тощо) та його параметри:

```cpp
// Клас драйвера дисплея
#define DISP_DRIVER_TYPE Arduino_ST7789

// Параметри конструктора драйвера дисплея (БЕЗ вказівника на шину)
#define DISP_DRIVER_PARAMS TFT_RST, DISPLAY_ROTATION, IS_IPS_DISPLAY, DISPLAY_WIDTH, DISPLAY_HEIGHT  

// У коді ініціалізації ці макроси розгортаються наступним чином:
Arduino_GFX* _output = new DISP_DRIVER_TYPE(&_bus, DISP_DRIVER_PARAMS);
```

Точний перелік параметрів та порядок їх передачі у конструктор для конкретного контролера дисплея чи шини можна переглянути у відповідних заголовкових файлах драйверів усередині бібліотеки `Arduino_GFX`.

<br>

#### 3. Роздільна здатність канвасу та калібрування зміщення (Offsets)

У файлі `graphics_config.h` окремо задаються розміри віртуального полотна (канвасу UI) та фізичні розміри матриці дисплея:

```cpp
#define UI_WIDTH 240        // Ширина канвасу UI
#define UI_HEIGHT 320       // Висота канвасу UI

#define DISPLAY_WIDTH 240   // Фізична ширина дисплея
#define DISPLAY_HEIGHT 320  // Фізична висота дисплея
```

У стандартному випадку ці значення однакові. Проте Pixeler дозволяє виводити GUI лише на частину екрана (`UI_WIDTH` / `UI_HEIGHT` менші за фізичну роздільну здатність). Це зручно, коли прошивка з одного пристрою запускається на іншій платі з більшим дисплеєм, а макети інтерфейсу ще не масштабовано під новий розмір.

<br>

::: {tip}
**Вирішення проблеми зміщення зображення (на прикладі Lilka v2):**  
На деяких невеликих дисплеях із нестандартною роздільною здатністю (наприклад, `240×280` з круглими кутами) під час зміни орієнтації (`DISPLAY_ROTATION`) зображення може частково виходити за межі екрана з однієї або двох сторін. Це пов'язано з тим, що внутрішній відеобуфер контролера (наприклад, ST7789 на `240×320`) більший за видиму область матриці.

Проблема вирішується взаємною заміною ширини й висоти для альбомної орієнтації та передачею параметрів зміщення (`col_offset` / `row_offset`) у кінець макросу `DISP_DRIVER_PARAMS`:
:::

```cpp
#define DISPLAY_ROTATION 3       // Стартова орієнтація дисплея (альбомна)

#define UI_WIDTH 280             // Ширина канвасу UI
#define UI_HEIGHT 240            // Висота канвасу UI

#define DISPLAY_WIDTH UI_HEIGHT  // Базова ширина матриці (240)
#define DISPLAY_HEIGHT UI_WIDTH  // Базова висота матриці (280)

// Останні 4 числа (0, 0, 0, 20) — апаратні відступи (offsets) матриці по осях X та Y
#define DISP_DRIVER_PARAMS TFT_RST, DISPLAY_ROTATION, IS_IPS_DISPLAY, DISPLAY_WIDTH, DISPLAY_HEIGHT, 0, 0, 0, 20
```
