### Карта пам'яті

Для взаємодії з картою пам'яті в Pixeler реалізовано власний файловий менеджер, який інтегровано до всіх бібліотек та класів фреймворку, що працюють із файловою системою.

Основні переваги вбудованого файлового менеджера порівняно зі стандартними бібліотеками Arduino:
* **Висока швидкодія:** Методи запису і читання працюють значно швидше завдяки блоковому обміну даними.
* **Швидке сканування каталогів:** Вбудовані методи для швидкого отримання списку файлів і папок, зокрема з фільтрацією за розширенням файлу.
* **Підтримка PSRAM:** Автоматично використовує зовнішню оперативну пам'ять (PSRAM) для буферів, якщо вона доступна на платі.
* **Потокобезпечність:** Усі операції захищені м'ютексами і можуть безпечно викликатися з різних потоків.
* **Асинхронні операції:** Копіювання та видалення можуть виконуватися у фоновій FreeRTOS-задачі на іншому ядрі, завдяки чому графічний інтерфейс (GUI) не блокується.
* **Рекурсивне видалення:** Підтримується видалення непорожніх каталогів разом з усім їхнім вмістом.

<br>

::: {warning}
Не використовуйте жодні сторонні способи взаємодії з картою пам'яті чи файлами під час роботи з Pixeler, окрім вбудованого файлового менеджера. Замість стандартного класу `FileStream` з Arduino за потреби використовуйте клас із файлу `pixeler/src/manager/file/FileStream.h`. Інакше поведінка коду буде невизначеною.
:::

::: {note}
Файловий менеджер доступний глобально в будь-якому класі контексту через об'єкт **`_fs`**. Опис додаткових допоміжних методів, які не розглянуто в цьому розділі, можна переглянути безпосередньо у файлі `pixeler/src/manager/FileManager.h` або через спливаючі підказки у вашій IDE.
:::

<br>

#### Налаштування

Усі апаратні налаштування карти пам'яті та її шини знаходяться у файлі `config/sd_config.h`. У ньому вказується інтерфейс обміну даними (номер шини **SPI** або слот **SD_MMC**), номери пінів підключення, максимальна частота шини тощо.

::: {note}
На різних моделях мікроконтролерів лінійки ESP номери доступних контролерів SPI та слотів SD_MMC можуть відрізнятися. Обов'язково звіряйтеся з технічною документацією (datasheet / pinout) для вашої конкретної плати.
:::

<br>

#### Монтування та демонтування

Перш ніж виконувати будь-які операції з файлами після запуску пристрою, карту пам'яті необхідно примонтувати та перевірити результат операції:

```cpp
if (_fs.mount())
{
  // Обробка успішного монтування
}
else
{
  // Обробка помилки монтування
}
```

Після завершення роботи з файловою системою (або перед переходом пристрою в глибокий сон / вимкненням) карту пам'яті рекомендується коректно відмонтувати:

```cpp
_fs.unmount();
```

::: {danger}
Перед викликом `_fs.unmount()` або перед вимкненням живлення пристрою необхідно обов'язково закрити всі відкриті файли. Інакше файлова система або дані на карті пам'яті можуть бути пошкоджені.
:::

<br>

#### Формат шляхів до файлів

Шляхи до файлів і папок для методів `_fs` завжди вказуються **без точки монтування** (вона додається менеджером автоматично):
* Для звернення до кореневого каталогу вказується шлях `"/"`.
* Для роботи з файлом у корені карти пам'яті — `"/some_file.txt"`.

<br>

#### Відкриття та закриття файлу

Для тривалої роботи з одним і тим самим файлом (наприклад, потокове передавання великого файлу по мережі чи аудіобуферизація) необхідно отримати вказівник `FILE*`:

```cpp
/**
 * @brief Повертає вказівник на бінарний файл, відкритий у вказаному режимі.
 *
 * @param path Шлях до файлу без точки монтування.
 * @param mode Режим відкриття файлу.
 * @return FILE* — вказівник на відкритий файл. 
 * @return NULL — якщо операція завершилася невдачею.
 */
FILE* openFile(const char* path, const char* mode);
```

Підтримуються стандартні режими відкриття файлів мови C:

| Режим | Призначення | Поведінка |
| :--- | :--- | :--- |
| **`"r"`** | Читання | Повертає `NULL`, якщо файл не знайдено. |
| **`"w"`** | Запис | Створює новий файл або повністю перезаписує існуючий. |
| **`"a"`** | Дозапис (Append) | Створює новий файл або додає дані в кінець існуючого. |
| **`"r+"`** | Читання та запис | Курсор на початку файлу. Файл обов'язково мусить існувати. |
| **`"w+"`** | Читання та запис | Якщо файл існує — очищує його вміст; якщо ні — створює новий. |
| **`"a+"`** | Читання та дозапис | Читання можливе з довільної позиції, але запис завжди відбувається в кінець файлу. |

<br>

Після завершення роботи з відкритим файлом його потрібно обов'язково закрити вручну:

```cpp
/**
 * @brief Закриває відкритий бінарний файл та обнуляє вказівник.
 *
 * @param file Посилання на вказівник на відкритий бінарний файл.
 */
void closeFile(FILE*& file);
```

<br>

#### Читання даних із файлу

Файловий менеджер пропонує три методи для читання даних залежно від вашої задачі.

##### 1. Одноразове читання без ручного відкриття файлу
Якщо потрібно одноразово вичитати невеликий файл (або його фрагмент) у буфер:

```cpp
/**
 * @brief Відкриває, читає бінарний файл за вказаним шляхом і автоматично закриває його.
 *
 * @param path Шлях до файлу без точки монтування.
 * @param out_buffer Вихідний буфер, куди будуть записані прочитані байти.
 * @param len Кількість байтів, які необхідно прочитати.
 * @param seek_pos Зміщення у байтах від початку файлу, з якого розпочати читання.
 * @return size_t — кількість успішно прочитаних байтів (0 у разі помилки).
 */
size_t readFile(const char* path, void* out_buffer, size_t len = 1, int32_t seek_pos = 0);
```

##### 2. Потокове читання з уже відкритого файлу
Якщо файл обробляється частинами у циклі, спочатку відкрийте його через `openFile()`, а потім використовуйте один із двох методів:

```cpp
/**
 * @brief Читає до len байтів із відкритого бінарного файлу.
 *
 * @param file Вказівник на відкритий файл.
 * @param out_buffer Вихідний буфер для записаних байтів.
 * @param len Кількість байтів для читання.
 * @param seek_pos Позиція від початку файлу у байтах.
 * @return size_t — фактична кількість успішно прочитаних байтів.
 */
size_t readFromFile(FILE* file, void* out_buffer, size_t len = 1, size_t seek_pos = 0);

/**
 * @brief Читає точну кількість байтів (len) із відкритого бінарного файлу.
 *
 * @param file Вказівник на відкритий файл.
 * @param out_buffer Вихідний буфер для записаних байтів.
 * @param len Точна кількість байтів, яку необхідно прочитати.
 * @param seek_pos Позиція від початку файлу у байтах (якщо 0 — читає з поточної позиції).
 * @return true — якщо вдалося прочитати рівно len байтів.
 * @return false — якщо прочитано менше байтів або сталася помилка.
 */
bool readFromFileExact(FILE* file, void* out_buffer, size_t len = 1, size_t seek_pos = 0);
```

* Використовуйте **`readFromFileExact()`**, коли критично отримати рівно `len` байтів (наприклад, під час читання заголовка структури чи кадру фіксованого розміру).
* Використовуйте **`readFromFile()`**, коли допускається зчитування довільної кількості байтів (наприклад, вичитування залишку файлу до кінця).

<br>

#### Запис даних у файл

Аналогічно до читання, доступні методи для одноразового запису за шляхом та для запису у вже відкритий файл:

```cpp
/**
 * @brief Створює або перезаписує файл та записує до нього байти з буфера.
 * Запис виконується оптимальними блоками для максимальної швидкодії.
 *
 * @param path Шлях до файлу без точки монтування.
 * @param buffer Буфер із даними для запису.
 * @param len Кількість байтів для запису.
 * @return size_t — кількість успішно записаних байтів (0 у разі помилки).
 */
size_t writeFile(const char* path, const void* buffer, size_t len);

/**
 * @brief Записує вказану кількість байтів до вже відкритого бінарного файлу.
 *
 * @param file Вказівник на відкритий файл.
 * @param buffer Буфер із даними для запису.
 * @param len Кількість байтів для запису.
 * @return size_t — кількість успішно записаних байтів (0 у разі помилки).
 */
size_t writeToFile(FILE* file, const void* buffer, size_t len);
```

Обидва методи автоматично скидають сторожовий таймер (**Watchdog Timer**), якщо запис великого буфера триває довго.

::: {warning}
Автоматичне скидання Watchdog-таймера **не спрацьовує**, якщо ви викликаєте метод запису у власному зовнішньому циклі дуже малими порціями даних. У такому разі розробник повинен самостійно контролювати час виконання своєї задачі.
:::

<br>

#### Видалення файлів та каталогів

Файловий менеджер підтримує три способи видалення:

##### 1. Синхронне видалення файлу (у поточному потоці)
```cpp
/**
 * @brief Видаляє файл у контексті поточної задачі.
 *
 * @param path Шлях до файлу без точки монтування.
 * @return true — якщо файл успішно видалено.
 */
bool rmFile(const char* path);
```

##### 2. Синхронне рекурсивне видалення каталогу (у поточному потоці)
```cpp
/**
 * @brief Рекурсивно видаляє папку разом із вмістом у контексті поточної задачі.
 *
 * @param path Шлях до папки без точки монтування.
 * @return true — якщо папку успішно видалено.
 */
bool rmDir(const char* path);
```

##### 3. Асинхронне видалення у фоновій задачі (на іншому ядрі МК)
```cpp
/**
 * @brief Запускає окрему задачу FreeRTOS для видалення файлу або папки у фоні.
 *
 * @param path Шлях до файлу або папки без точки монтування.
 * @return true — якщо фонову задачу було успішно створено та запущено.
 * @return false — якщо вже працює інша фонова задача _fs або не вдалося створити задачу.
 */
bool startRemoving(const char* path);
```

<br>

::: {warning}
Повернення `true` з методу `startRemoving()` означає лише те, що **фонову задачу було успішно запущено**, а не фінальний успіх видалення всіх файлів.
:::

Приклад очікування або перевірки результату фонового видалення:

```cpp
bool result = false;
if (_fs.startRemoving(path))
{
  while (_fs.isWorking())
    delay(2);

  result = _fs.lastTaskResult();
}
else
{
  // Не вдалося запустити фонову задачу
}
```

Запуск `startRemoving()` із подальшим блокуючим циклом `while` у потоці UI не має практичного сенсу — асинхронне видалення варто використовувати саме тоді, коли в інтерфейсі реалізовано показ індикатора виконання або кнопку скасування операції.

* Фоolову задачу видалення можна зупинити достроково — вона завершиться одразу після видалення поточного елемента. Вже видалені файли відновленню не підлягають.
* Видалення каталогу працює рекурсивно. Уникайте надмірної глибини вкладеності підкаталогів, щоб не спричинити переповнення стеку викликів (`stack overflow`).

<br>

#### Копіювання файлів

Копіювання файлів виконується виключно в асинхронному режимі у фоновій FreeRTOS-задачі (копіювання цілих каталогів наразі не підтримується):

```cpp
/**
 * @brief Запускає окрему задачу FreeRTOS для копіювання бінарного файлу у фоні.
 *
 * @param from Шлях до вихідного файлу без точки монтування.
 * @param to Цільовий шлях для копії файлу без точки монтування.
 * @return true — якщо фонову задачу копіювання успішно створено та запущено.
 * @return false — якщо вже працює інша фонова задача _fs або запуск не вдався.
 */
bool startCopyingFile(const char* from, const char* to);
```

::: {warning}
Повернення `true` з виклику `startCopyingFile()` означає лише успішний **запуск задачі копіювання**, а не її завершення. Одночасно може працювати лише одна фонова задача файлового менеджера.
:::

Приклад копіювання файлу з неблокуючим оновленням смуги прогресу (`ProgressBar`) через механізм `post()`:

```cpp
// Обробник зворотного виклику прогресу копіювання (0..100%)
void FilesContext::copyProgressHandler(uint8_t progress, void* arg)
{
  FilesContext* self = static_cast<FilesContext*>(arg);
  self->post([self, progress]()
             { self->updCopyProgress(progress); }, 0);
}

// Обробник зворотного виклику завершення фонової задачі
void FilesContext::taskDoneHandler(bool result, void* arg)
{
  FilesContext* self = static_cast<FilesContext*>(arg);
  self->post([self, result]()
             { self->handleTaskDone(result); }, 500);
}

// Підписуємося на події прогресу та завершення
_fs.onCopyProgress(copyProgressHandler, this);
_fs.onTaskDone(taskDoneHandler, this);

// Запускаємо фонове копіювання
if (!_fs.startCopyingFile(old_file_path.c_str(), new_file_path.c_str()))
  showToast(STR_FAIL, TOAST_LENGTH_SHORT); // Повідомлення у разі помилки старту
else
  showCopyingTmpl(); // Відображаємо вікно з прогрес-баром
```

У цьому прикладі смуга прогресу плавно оновлюється під час копіювання, кнопки пристрою залишаються чутливими, а користувач може в будь-який момент скасувати копіювання (при скасуванні неповну копію файлу буде автоматично видалено).

<br>

#### Перейменування та переміщення

Перейменування та переміщення виконуються одним універсальним методом як для файлів, так і для каталогів:

```cpp
/**
 * @brief Перейменовує або переміщує файл чи каталог.
 *
 * @param old_name Поточний шлях до файлу або каталогу без точки монтування.
 * @param new_name Новий шлях до файлу або каталогу без точки монтування.
 * @return true — якщо операція виконана успішно.
 */
bool rename(const char* old_name, const char* new_name);
```

<br>

#### Потокобезпечність

Усі методи файлового менеджера `_fs` є повністю потокобезпечними — їх можна без додаткової синхронізації викликати одночасно з різних задач FreeRTOS, що виконуються на різних ядрах мікроконтролера.
